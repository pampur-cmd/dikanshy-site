# Технические границы и будущий выбор стека

Статус: стек корпоративного сайта не выбран; задача T28 после согласования дизайна. Версии и команды запуска из feed не подтверждены для этого репозитория.

## Требования

- Три языка, единые идентификаторы товаров, две темы и адаптивные страницы.
- Серверный приём обращений: контакт телефон либо email, позиции, необязательные количества и единицы, язык и согласованный набор дополнительных полей.
- База — источник сохранённых обращений; номер и успех только после записи. Повтор запроса не создаёт дубликат.
- Telegram-уведомления, закрытый доступ сотрудников, выборка по датам и экспорт таблицы. Ошибка доставки не отменяет запись обращения.
- Собственный сервер и совместная маршрутизация с feed учитываются по локальному плану миграции. Рабочие данные не подменяются тестовыми стендами.

## Что можно оценить из feed в T28

Подходы к локализации, темам, серверной валидации, транзакциям, уникальному ключу отправки, очереди уведомлений и повторной доставке. Next.js/TypeScript/PostgreSQL и отдельный worker — возможный вариант, не принятое решение.

Не подключать автоматически его базу, бота, кабинеты, Google Sheets, калькулятор, корзину и зависимости. Повторное использование кода требует проверки назначения, лицензий, актуальности и изоляции данных. Существующие настройки `.env` не копировать.

## До разработки

Не создавать `site/`, package.json, миграции, серверы или технический каркас в рамках организации документов и сбора референсов. После T27–T28 будущие исходники размещать в `site/` по отдельной задаче T29.

Перед установкой определить текущие совместимые версии по официальной документации, закрепить реально выбранные зависимости и записать проверенные команды. Не объявлять сборку, тесты, базу или бот работающими на основании опыта соседнего проекта.

## Проверки будущей реализации

Проверки выбирать по риску и фактическим изменениям. Особенно важны сохранение обращения, повторы после сбоя, изоляция доступа, границы периода, полнота строк и объёмов в выгрузке. Для документации проверять ссылки, ID задач и соответствие статусов; приложение для этого не запускать.

Секреты, дампы, настоящие обращения и экспорт с контактами не хранить в репозитории. Конфигурация рабочего окружения и инструкции восстановления появятся по задачам T28, T43–T46.

Отдельный iframe/Oracle-хостинг сам по себе не переносит рендеринг на сервер. Удалённая генерация интерактивного видео — другая архитектура, пока не выбрана.
